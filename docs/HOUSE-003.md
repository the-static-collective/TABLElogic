# HOUSE-003 — ONE QUESTION / MANY POSSIBILITIES / NO SILENT ACT

**Status: DRAFT / HOLD / experimental native specimen, not production.**

TABLElogic HOUSE-001 demonstrated original planZ × CANNON × GHoT × reLATTE × STATIC OS. HOUSE-002 exercised original Workbench × JAR;VIS × webZ × GRAFT, but the JAR;VIS garden example was deliberately unrelated to the question.

**HOUSE-003 fixes that specific absence.** The original question is now the address of every hypothetical review proposal. An original Workbench candidate reading and original webZ catalog candidate jointly identify each proposal. The original JAR;VIS engine produces a separate HOLD. A local human choice yields an unsigned return, never an external action.

## What changed

1. Original Workbench APERTURE preserves the exact question and its gaps. Ambiguity remains alternatives, not an automatic meaning selection.
2. Original webZ Ask JAR;VIS assemble(question) chooses three candidate public capability descriptions. The question determines candidate selection. Its fetcher is offline; only the pinned GRAFT/main README may be retrieved locally. Other sources remain UNAVAILABLE.
3. TABLElogic synthesizes a clearly hypothetical need and offer for each Workbench reading × webZ catalog candidate. The pair is declared as generic question-attention-fixture, not a fact about real people, available resources, compatible organizations, or human intent.
4. For each hypothetical pair, original source-pinned JAR;VIS Jar → propose → cross produces its own native HOLD receipt because there are no grants. These are question-bound structural proposals, not semantic matches, actual invitations, deployed agents, or live services.
5. The original GRAFT graft/circle nursery manifest contributes its STAGING/HOLD and NO_CODE_IMPORTED information only when GRAFT is among the selected catalog candidates. No private origin source is read or copied.
6. A participant can locally choose KEEP_AS_QUESTION, INVITE_LOCAL_REVIEW, or DECLINE. The choice is bound to the exact encounter address and produces a create-only unsigned record. It is never sent to recipients.

This demonstrates question-specific ADDRESS BINDING—not general-purpose natural-language reasoning. It doesn't claim to solve the semantic interpretation or human permission problems.
